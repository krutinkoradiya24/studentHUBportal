## 3. Security Architecture & Threat Defense Checklist

| Security Area | Implementation Technique | Compliance Status | Proof / Location |
| :--- | :--- | :---: | :--- |
| **Role-Based Access Control (RBAC)** | Strict server-side verification using `require_admin()` and `require_student()`. Students are denied access to `/admin/` and redirected with `admin_access_denied`. | ✅ VERIFIED | `includes/rbac.php`, `includes/admin_header.php`, `includes/student_header.php` |
| **Password Storage** | Passwords stored strictly as Bcrypt cryptographic hashes generated by `password_hash($password, PASSWORD_BCRYPT)`. Plaintext passwords are never logged or stored. | ✅ VERIFIED | `includes/auth_helpers.php` (line 140), `data/seed.php` |
| **CSRF Defense** | Cryptographically secure tokens (`bin2hex(random_bytes(32))`) bound to session state. Submissions validated with timing-attack resistant `hash_equals()`. | ✅ VERIFIED | `includes/session.php`, `login.php`, `register.php`, `admin/attendance.php` |
| **Session Fixation Prevention** | Session IDs are regenerated upon successful authentication via `session_regenerate_id(true)`. | ✅ VERIFIED | `includes/auth_helpers.php` (line 72), `tests/test_suite.php` (Test 19) |
| **Session Expiration** | Enforces a strict 15-minute (900 seconds) inactivity timeout. Expired sessions are automatically destroyed and redirected to login with `error=timeout`. | ✅ VERIFIED | `includes/session.php` (lines 40-52), `tests/test_suite.php` (Test 20) |
| **SQL Injection Defense** | All database queries utilize PDO and MySQLi prepared statements with strictly typed bound parameters (`execute([:param])` or `bind_param()`). Zero raw SQL concatenation. | ✅ VERIFIED | `includes/auth_helpers.php`, `admin/*.php`, `student/*.php` |
| **Cross-Site Scripting (XSS)** | Dynamic outputs are sanitized using `htmlspecialchars($string, ENT_QUOTES, 'UTF-8')` wrapped in an escape helper `e()`. | ✅ VERIFIED | `includes/session.php` (line 103), all view templates |
| **Authentication Policy** | Only registered users can sign in. Unregistered emails or invalid passwords are systematically rejected with generic, security-safe error messages. | ✅ VERIFIED | `login.php`, `includes/auth_helpers.php`, `Frontend/html/login.html` |

## 4. Accessibility (WCAG 2.1 AA) Compliance Checklist

| Accessibility Guideline | Implementation Details | Status |
| :--- | :--- | :---: |
| **Semantic Structure** | Proper HTML5 hierarchy (`<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`, `<h1>` through `<h3>`). | ✅ Pass |
| **Form Labels & Associates** | Every input field possesses an explicit `<label for="...">` linking programmatic focus. | ✅ Pass |
| **ARIA Attributes** | Interactive icons include `aria-label`, hamburger toggles include `aria-expanded`, and errors include `aria-invalid` and `aria-describedby`. | ✅ Pass |
| **Color Contrast Ratios** | All text meets or exceeds WCAG AA 4.5:1 ratio (Navy `#1e3a8a` on white `#ffffff` = 8.5:1, Dark cards `#1e1b4b` with light accents). | ✅ Pass |
| **Keyboard Navigability** | Full keyboard support: `Tab` for focusable elements, `Escape` key closes all active admin modals, `Enter`/`Space` triggers buttons. | ✅ Pass |
| **Theme & Dark Mode** | Persistent Light/Dark theme toggle using CSS custom properties with high-contrast text rendering. | ✅ Pass |
| **Screen Reader Fallbacks** | Modals, toasts, and status pills utilize clear text alternatives and font-awesome icons with accompanying textual descriptions. | ✅ Pass |
